## 一、项目生产打包方案

### 1.1 当前项目结构分析

```
src/frontend/
├── app/
│   ├── layout.tsx          ← 根布局
│   ├── page.tsx            ← 首页（岗位选择）
│   ├── globals.css         ← 全局样式
├── components/
│   ├── ChatArea.tsx         ← 面试对话区（核心）
│   ├── FaceCapture.tsx      ← 摄像头采集（含 MediaPipe 动态导入）
│   ├── VoiceRecord.tsx      ← 语音录音（Web Speech API）
│   ├── ResumeUpload.tsx     ← 简历上传（mammoth 解析）
│   ├── ReportView.tsx       ← 报告页（雷达图+PDF/Word导出）
│   └── RecordsView.tsx      ← 面试记录
├── lib/
│   └── api.ts              ← API 通信层（fetch /api/chat）
├── next.config.js           ← 含 rewrites 代理
├── package.json             ← Next.js 14.2.35
└── tailwind.config.js
```

**关键发现：** `next.config.js` 使用了 `async rewrites()` 将 `/api/*` 代理到 `http://localhost:8000`。rewrites 需要 Node.js 运行时，这意味着：
- **SSR 模式**（`next start`）：rewrites 正常工作，前后端同机部署最简单
- **静态导出模式**（`output: 'export'`）：rewrites 失效，前端需直连后端 API 地址，后端需配置 CORS

### 1.2 打包方案选择

| | SSR 模式（推荐） | 静态导出模式 |
|---|---|---|
| 适用场景 | 自有 Linux 服务器 | Vercel/阿里云OSS/腾讯云静态托管 |
| API 代理 | rewrites 原生支持 | 需要改为直连 URL + 后端 CORS |
| 构建命令 | `next build` | `next build`（需加 `output: 'export'` 配置） |
| 运行方式 | `next start -p 3000` | 纯静态文件，扔进 Nginx/OSS |
| 产物目录 | `.next/` | `out/` |
| MediaPipe | 支持，public/ 目录正常服务 | 同上 |

### 1.3 SSR 模式打包完整命令

```bash
# 1. 进入前端目录
cd /path/to/project_002_多模态Agent智能面试评估系统/src/frontend

npx tsc --noEmit

# 4. 生产构建
npm run build
# 等价于: next build

# 5. 启动生产服务
npm run start

# 或使用 PM2
pm2 start npm --name "interview-frontend" -- run start
```

产物目录 `src/frontend/.next/` 说明（无需手动操作，Next.js 内部使用）：
```
.next/
├── standalone/     ← standalone 模式产物（后续可配置）
├── static/         ← 静态资源（JS/CSS chunks）
├── server/         ← SSR 服务端代码
└── BUILD_ID        ← 构建版本号
```

### 1.4 打包常见报错处理

| 报错 | 原因 | 解决 |
|---|---|---|
| `SyntaxError: Unexpected token '﻿'` | package.json 含 BOM 头（UTF-8 with BOM） | 用 VS Code 右下角编码改为 "UTF-8 without BOM" 保存 |
| `Module not found: Can't resolve 'xxx'` | 依赖未安装或路径错误 | `npm install` 重新安装 |
| `Type error: Cannot find name 'xxx'` | TypeScript 类型问题 | `npx tsc --noEmit` 逐项修复 |
| `Error: > Build failed because of webpack errors` | 一般是 Tailwind 配置问题 | 检查 `tailwind.config.js` 的 `content` 路径是否覆盖所有组件 |
| `npm: 无法加载文件 ... 禁止运行脚本` (PowerShell) | Windows 执行策略限制 | 在 cmd 中运行，或 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |

## 二、MediaPipe 人脸模型线上资源兼容改造

### 2.1 问题分析

`FaceCapture.tsx` 第 92-94 行动态导入 MediaPipe 时，`locateFile` 指向境外 CDN：

```typescript
const { FaceMesh } = await import("@mediapipe/face_mesh");
const faceMesh = new FaceMesh({
  locateFile: (f: string) => `https://cdn.jsdelivr.net/npm/@mediapipe/face_mesh@0.4/${f}`,
});
```

问题：(1) 境外 CDN 可能不可达；(2) WASM 文件加载后 `buffer` 属性未定义 → 黑屏；(3) 公网访问需要正确的 MIME 类型和跨域头。当前代码已有降级——MediaPipe 加载失败时静默使用 `simulateFaceData()`，不影响主流程。但我们将改进为优先加载本地文件。

### 2.2 离线本地引入方案

**第一步：下载 MediaPipe 资源文件到 public 目录**

在 `src/frontend/public/` 下创建 `mediapipe/face_mesh/` 目录，放入以下文件：

```
public/mediapipe/face_mesh/
├── face_mesh_solution_packed_assets_loader.js
├── face_mesh_solution_simd_wasm_bin.wasm
├── face_mesh_solution_packed_assets.data
├── face_landmarker.task          ← 可选，新版 Task API
└── face_mesh.binarypb             ← 可选
```

获取方式：
```bash
# 方式一：从 npm 包中复制
cp -r node_modules/@mediapipe/face_mesh/* public/mediapipe/face_mesh/

# 方式二：从 jsdelivr CDN 下载（在可访问的网络环境下）
# 浏览器访问 https://cdn.jsdelivr.net/npm/@mediapipe/face_mesh@0.4/
# 下载所有文件放入 public/mediapipe/face_mesh/
```

**第二步：修改 FaceCapture.tsx 的 locateFile 逻辑**

当前代码的 MediaPipe 加载在 try-catch 内，MediaPipe 失败会自动降级为模拟数据。为了线上稳定性，新增一个"优先本地、失败降级CDN、再失败降级模拟"的三级加载策略。新增代码标注 `[DEPLOY]`，不侵入原有组件逻辑。

**第三步：Nginx WASM MIME 类型配置**

```nginx
# 在 nginx.conf 的 http 或 server 块中添加
types {
    application/wasm  wasm;
}

# 或者在 mime.types 中添加
# application/wasm wasm;
```

**第四步：WASM 跨域配置（云托管场景）**

如果 WASM 文件托管在独立的 COS/OSS 上，需要配置跨域：

```xml
<!-- 阿里云 OSS 跨域规则 -->
<CORSConfiguration>
    <CORSRule>
        <AllowedOrigin>*</AllowedOrigin>
        <AllowedMethod>GET</AllowedMethod>
        <AllowedHeader>*</AllowedHeader>
        <ExposeHeader>Content-Length</ExposeHeader>
        <MaxAgeSeconds>3600</MaxAgeSeconds>
    </CORSRule>
</CORSConfiguration>
```

**第五步：在 next.config.js 中确保 WASM 文件被正确处理**

```javascript
// next.config.js 新增 [DEPLOY]
const nextConfig = {
  // ... 原有 rewrites 保持不变

  // [DEPLOY] 确保 WASM 文件正确设置响应头
  async headers() {
    return [
      {
        source: "/mediapipe/:path*",
        headers: [
          { key: "Cross-Origin-Opener-Policy", value: "same-origin" },
          { key: "Cross-Origin-Embedder-Policy", value: "require-corp" },
        ],
      },
    ];
  },

  // [DEPLOY] webpack 配置：允许 WASM 导入
  webpack: (config) => {
    config.experiments = { ...config.experiments, asyncWebAssembly: true };
    return config;
  },
};
```

## 三、HTTPS 环境适配配置

### 3.1 为什么必须 HTTPS

Chrome/Firefox/Safari 的规定：`getUserMedia()`（摄像头+麦克风）仅在以下情况可用：
- `localhost`（开发豁免）
- HTTPS 页面
- `file://` 协议（部分浏览器）

公网域名使用 HTTP 时，`navigator.mediaDevices.getUserMedia()` 会直接抛出 `NotAllowedError`。

### 3.2 SSL 证书获取

| 方案 | 适用 | 费用 | 操作 |
|---|---|---|---|
| Let's Encrypt (certbot) | 自有 Linux 服务器 | 免费 | `certbot --nginx -d your-domain.com` |
| 阿里云免费SSL | 阿里云 ECS + 域名 | 免费 | 阿里云控制台 → SSL证书 → 免费证书（一年） |
| 腾讯云免费SSL | 腾讯云 CVM + 域名 | 免费 | 腾讯云控制台 → SSL证书 → 免费证书 |
| Cloudflare | 任何服务器（通过CF代理） | 免费 | DNS 接入 Cloudflare → SSL/TLS 选 Flexible |

**推荐**：如果你有一台 Linux 服务器 + 域名，用 Let's Encrypt 最方便，一条命令搞定。

### 3.3 Nginx HTTPS 完整配置

```nginx
server {
    listen 80;
    server_name your-domain.com;
    # HTTP 自动跳转 HTTPS
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    # SSL 证书路径（Let's Encrypt 默认）
    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    # SSL 安全配置
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;

    # WASM MIME 类型
    types {
        application/wasm wasm;
    }

    # 前端静态资源（Next.js SSR 模式）
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket 支持（Next.js HMR 用到）
        proxy_read_timeout 86400;
    }

    # API 后端代理
    location /api/ {
        proxy_pass http://127.0.0.1:8000/api/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;  # Agent 决策可能较慢
    }

    # 静态资源缓存
    location /_next/static/ {
        proxy_pass http://127.0.0.1:3000/_next/static/;
        proxy_cache_valid 200 365d;
        add_header Cache-Control "public, immutable, max-age=31536000";
    }

    # MediaPipe 资源
    location /mediapipe/ {
        proxy_pass http://127.0.0.1:3000/mediapipe/;
        add_header Cross-Origin-Opener-Policy "same-origin";
        add_header Cross-Origin-Embedder-Policy "require-corp";
    }

    # 安全头
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # Gzip
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript application/wasm;
    gzip_min_length 1000;
}
```

### 3.4 自签名证书（仅测试用）

## 五、线上环境文件导出兼容适配

### 5.1 当前导出机制分析

| 导出格式 | 当前实现 | 原理 | 线上兼容性 |
|---|---|---|---|
| PDF | `handleExportPDF()` → `window.print()` | 浏览器原生打印 | ✅ 纯客户端，无兼容问题 |
| Word | `handleExportWord()` → `Blob` + `URL.createObjectURL()` → `<a download>` | 客户端生成 HTML → 转 Blob → 触发下载 | ✅ 纯客户端 |
| 雷达图（SVG） | 内联 SVG 在 JSX 中渲染 | React 组件渲染 | ⚠️ Word 导出时需要转为表格（已处理） |

### 5.2 线上环境补充适配

**（1）Word 导出 BOM 头处理**

当前代码在 Blob 前加了 `﻿`（BOM）确保中文不乱码：
```typescript
var blob = new Blob(["﻿" + html], { type: "application/msword" });
```
线上环境此逻辑无变化，继续使用。

**（2）大文件下载超时处理**

18维评分 + 多轮QA 的 Word 报告 HTML 可能达到 200KB+，下载触发时：
- 使用 `URL.createObjectURL`（内存中生成，不存在网络超时）
- `a.click()` 触发浏览器下载，不经过网络请求
- 下载完成后 `URL.revokeObjectURL` 释放内存

**线上无额外风险。** 唯一需要确认：Nginx 没有对 `/` 路径设置过小的 `client_max_body_size`（导出不经过 Nginx 请求，所以不受影响）。

**（3）字体兼容**

Word 导出使用 `font-family: 'Microsoft YaHei', sans-serif`：
- Windows：微软雅黑系统自带 ✅
- macOS/Linux：降级为 sans-serif，排版会略有差异但不影响内容
- **不需要**引入在线字体，避免外链加载失败

### 5.3 不需要修改的部分

- PDF 导出：`window.print()` 纯浏览器API，无网络依赖
- Word 导出：`Blob + a.download`，纯客户端
- 报告页面渲染：纯 React SSR/静态，无外部依赖
- 所有导出逻辑保持不变，仅验证线上 HTTPS 下 `Blob` 和 `URL.createObjectURL` 是否正常工作（已验证：这两个 API 在所有现代浏览器 HTTPS 环境下完全可用）

## 六、线上异常兜底优化补充

### 6.1 新增全局异常兜底组件

创建 `src/frontend/components/DeployErrorBoundary.tsx`（新文件，仅用于部署适配）：

```tsx
// [DEPLOY] 线上异常兜底组件 — 不侵入任何原有组件
"use client";
import { useEffect, useState } from "react";

interface Props {
  children: React.ReactNode;
  onResourceError?: (resource: string, type: string) => void;
}

export default function DeployErrorBoundary({ children, onResourceError }: Props) {
  const [resourceErrors, setResourceErrors] = useState<string[]>([]);
  const [showBanner, setShowBanner] = useState(false);

  useEffect(() => {
    // 全局资源加载失败监听
    const handler = (e: ErrorEvent) => {
      const target = e.target as HTMLElement;
      if (target && (target.tagName === "SCRIPT" || target.tagName === "LINK" || target.tagName === "IMG")) {
        const src = (target as any).src || (target as any).href || "";
        if (src.includes("mediapipe") || src.includes("wasm") || src.includes("face_mesh")) {
          const msg = "面部识别资源加载失败，已降级为模拟模式";
          setResourceErrors(prev => [...prev, msg]);
          setShowBanner(true);
          onResourceError?.(src, "mediapipe");
        }
      }
    };
    window.addEventListener("error", handler, true);
    return () => window.removeEventListener("error", handler, true);
  }, [onResourceError]);

  // 全局未捕获 Promise 异常（如 fetch 超时）
  useEffect(() => {
    const handler = (e: PromiseRejectionEvent) => {
      if (e.reason?.message?.includes("fetch") || e.reason?.message?.includes("network")) {
        setResourceErrors(prev => [...prev, "网络连接异常，请检查网络后刷新页面"]);
        setShowBanner(true);
      }
    };
    window.addEventListener("unhandledrejection", handler);
    return () => window.removeEventListener("unhandledrejection", handler);
  }, []);

  return (
    <>
      {showBanner && (
        <div className="fixed top-0 left-0 right-0 z-[9999] bg-[#d2991d22] border-b border-[#d2991d55] px-4 py-2 text-center">
          <span className="text-[#d2991d] text-xs font-medium">
            {resourceErrors[resourceErrors.length - 1]}
          </span>
          <button
            onClick={() => setShowBanner(false)}
            className="ml-3 text-[#8b949e] hover:text-white text-xs">
            ✕
          </button>
        </div>
      )}
      {children}
    </>
  );
}
```

### 6.2 摄像头/麦克风权限拒绝提示（已有，需确认）

`FaceCapture.tsx` 和 `VoiceRecord.tsx` 已内置了权限拒绝的 alert 提示：

- "麦克风权限被拒绝"

### 6.3 API 请求超时兜底

修改 `lib/api.ts` 的 fetch 调用（新增超时逻辑，不改变原有请求体）：

```typescript
  method: "POST",
```

## 八、配套运维说明

### 8.1 静态资源缓存策略

| 资源类型 | 路径 | 缓存策略 | 原因 |
|---|---|---|---|
| Next.js 构建产物 | `/_next/static/*` | `Cache-Control: public, immutable, max-age=31536000` | 文件名含 hash，内容变化 URL 也变化 |
| MediaPipe WASM | `/mediapipe/*` | `Cache-Control: public, max-age=604800` | 7天，模型文件不常变 |
| public 静态文件 | `/*.png, /*.ico, /*.svg` | `Cache-Control: public, max-age=86400` | 1天 |
| HTML 页面 | `/` 及所有非静态路径 | `Cache-Control: no-cache` | SSR 页面需每次验证 |

### 8.3 环境变量线上配置规范

**前端环境变量（`.env.production`）：**

```bash
# 前端 — src/frontend/.env.production
NEXT_PUBLIC_API_URL=https://your-domain.com/api
NEXT_PUBLIC_APP_NAME=智能面试评估系统
```

**后端环境变量（`config/.env.production`）：**

```bash
# 后端 — config/.env.production
APP_NAME=智能面试评估系统
APP_VERSION=0.1.0
HOST=127.0.0.1
PORT=8000
CORS_ORIGINS=["https://your-domain.com"]
CHATGLM_API_URL=http://localhost:7860
CHATGLM_MODEL=THUDM/chatglm3-6b
CHROMA_HOST=localhost
```

**环境变量使用原则：**
- 前端用 `NEXT_PUBLIC_` 前缀（Next.js 编译时注入，浏览器可读）
- 后端用 `python-dotenv` 或 `pydantic-settings` 读取
- 密钥类（API Key）不放前端环境变量
- 不同环境用不同 `.env` 文件：`.env.development` / `.env.production`
