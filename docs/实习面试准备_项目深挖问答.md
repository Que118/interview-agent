# 实习面试准备手册 — 项目深挖问答（基于 agent-interview.cn）

> 用途：面试前2小时速览 + 面试前夜精读
> 核心原则：**答得出来的细节才写进简历，答不出来的先复习**。所有回答与项目代码一一对应。

---

## 一、30秒项目介绍（必背模板）

"我做的是一个**基于多模态 Agent 的智能面试评估系统**。它不是传统那种固定题库的 AI 面试工具——传统工具所有人刷同一套题，我的系统会根据候选人的实时表现自己决定下一题问什么。

核心流程是：候选人回答之后，系统从**文本、语音、视觉**三个模态并行打分，融合成 18 个维度的评估向量，然后一个基于状态机的 Agent 决策引擎根据这 18 维做决策——深挖弱点、转话题、给提示或者结束面试——再从 500 多条知识库里检索相关内容，生成有针对性的下一题。

技术栈是 Next.js + FastAPI，Agent 用 Python 手写状态机，视觉分析在浏览器端跑 MediaPipe 保证隐私合规。项目已经部署上线了，https://agent-interview.cn 可以直接体验。"

## 二、面试官最可能追问的 12 个问题

### Q1：这个项目的难点/亮点是什么？

**回答要点（挑2-3个说，别贪多）：**

1. **决策与生成分离**：市面上大多数"AI面试官"是直接把面试过程塞给 LLM 一个 prompt，让大模型自己决定问什么——这是黑箱，大模型可能跑偏。我的设计是：状态机规则引擎做决策（可解释、可追溯），LLM 只负责把决策结果转成自然语言（生成自然）。决策错了能定位到是哪条规则，生成不好了换 LLM 就行，两者解耦。

2. **18维多模态融合 + 降级容错**：三个模态并行分析，但任何一个模态挂了（比如摄像头权限被拒、WASM加载失败）系统不会崩——该模态填中性分50，权重自动分配给其他模态，最坏情况退化成纯文本面试，流程照跑。

3. **隐私设计**：视觉分析在浏览器端本地跑 MediaPipe，只把13个数值特征（眼睛开合度、视线方向这些）传给后端，**人脸视频本身不出浏览器**。

### Q2：Agent 怎么决定"深挖/转题/提示/结束"？讲一下决策逻辑。

**回答模板（这就是 agent.py 里 DecisionStrategy.decide 的规则）：**

"我用的是一个**显式规则状态机**，7条规则按优先级从上往下匹配，命中就执行：

- 首轮 → 开场白
- 轮次到12轮 → 结束
- 连续3轮总分低于35 → 主动结束（保护候选人，避免一直打击他）
- 本轮总分低于35 → 给提示（降低难度）
- 弱点维度≥3个且总分≥45 → 转话题（这个方向他不擅长，换一个）
- 弱点维度≥2个 → 深挖弱点（追问薄弱点确认真实水平）
- 总分≥70且强维度≥3 → 转话题（他擅长，不用继续问，扩大考察面）
- 总分<48 → 给提示
- 兜底 → 深挖

状态机里维护了几个状态量：当前轮次、每轮历史、各维度的连续弱点命中次数、已覆盖话题列表、压力指数。压力指数是累积的——低分轮+0.15，正常轮-0.05，上限1.0。

为什么不用让 LLM 直接决策？因为面试决策需要**可解释性**——老师问"为什么这轮转话题"，我能指着规则说"因为他的弱点维度≥3"，LLM 黑箱给不出这个答案。"

### Q3：18个维度都是什么？怎么算分的？

**必背结构（说不出18个就按组背）：**

文本5维：关键词覆盖、结构逻辑、术语准确、简历匹配、信息密度
语音5维：语速节奏、停顿卡壳、语调情感、流利重复、音量清晰
视觉4维：眼神注意、面部表情、头部手势、形象背景
融合4维：跨模态一致性、综合压力、时间连贯性、个性化综合

**每个维度至少要能说出"输入什么特征、怎么算"其中一个例子：**

- 关键词覆盖：岗位关键词库（如前端岗30个词），命中数×14+18分，非线性——面试单题不需要覆盖全部
- 结构逻辑：正则检测5类信号（序号"首先/然后"、总分"综上"、因果"因为所以"、并列"同时/另外"、对比"但是/然而"），每类20分
- 信息密度：实体密度（技术词/数字/专有名词占比）+ 停用词惩罚（"嗯啊就是那个"比例越高分越低）
- 语速节奏：VAD能量检测切分有声段，理想词速160-280字/分钟
- 眼神注意：眼睛开合度10% + 视线偏移45% + 视线稳定20% + 眨眼频率25%
- 跨模态一致性：三模态总分的变异系数CV，CV>0.45说明"嘴里说自信、身体很紧张"，判为严重不一致
- 压力指数：文本压力0.35权重 + 语音0.35 + 视觉0.15 + 历史累积0.15

### Q4：语音分析具体怎么做的？用没用 Whisper？

**回答模板：**

"语音5维的**声学特征分析**是我自己用 Python 标准库写的——wave 读 WAV、struct 解16bit PCM、然后三个核心算法：
- **VAD 语音活动检测**：能量阈值0.015切分有声段/静默段，用于算停顿卡壳和语速
- **过零率 ZCR**：信号符号变化率，估算频率特性，用于算音调变化和清晰度
- **RMS 能量**：音量评估

语音**转文字**用浏览器自带的 Web Speech API，零部署成本。

为什么没用 Whisper 在服务器跑？第一，实时性——浏览器端转写零延迟；第二，隐私——音频不用出浏览器；第三，我的分析管道只需要声学特征，不需要等转写结果。Whisper 作为后续增强项写在了论文展望里，架构上语音管道的输入是标准WAV流，接 Whisper 只改上游。"

### Q5：视觉分析怎么做的？摄像头数据会传到服务器吗？

**回答模板：**

"不会传。整个链路是：
1. 浏览器 getUserMedia 拿摄像头流
2. 本地跑 MediaPipe Face Mesh，提取468个面部关键点
3. 前端从关键点算出13个数值特征：眼睛开合度、眨眼频率、视线偏移量、头部三轴角度、头部运动幅度、微笑比例、表情方差、检测置信度
4. 只有这13个数字进后端，视频流、图像帧全部不离开浏览器

这是隐私合规的关键设计——候选人的脸不出现在服务器上。

还有一个工程细节：MediaPipe 的 WASM 模型文件从 CDN 加载不稳定（会报 buffer undefined 的黑屏问题），我做了**三级降级**：本地离线WASM → CDN回退 → 模拟数据兜底。就算人脸识别完全挂了，面试流程照常跑，只是视觉维度变中性分。"

### Q6：LLM 部分是怎么接的？用的哪个模型？

**回答模板（这是最容易翻车的问题，要诚实但讲清设计）：**

"我设计了一个 BaseLLM 抽象层，定义统一的 chat/health 接口，下面两个实现：
- ChatGLMClient：走 OpenAI 兼容协议的 HTTP 调用，配 base_url 和 model 即可
- MockLLM：本地开发模式用的结构化出题器

为什么做双模式？ChatGLM-6B 本地部署要16G以上显存，我个人的机器跑不了，云 API 开发期又烧钱。MockLLM 按'岗位×决策类型'组织题库，每次会话 random.shuffle 打乱，保证同一会话内题目不重复、不同会话顺序不同——这样整个 Agent 决策链路、知识检索、18维评分都可以在零 LLM 依赖下完整开发和测试。等部署环境有 GPU 或 API Key，一行配置就切过去，其他代码零改动。

这个设计还验证了'决策与生成分离'——决策从来不依赖 LLM。"

### Q7：知识库/RAG 怎么实现的？500条数据哪来的？

**回答模板：**

"知识库是结构化 JSON，501条，按'岗位×维度×话题'三级组织，覆盖前端、后端、数据分析、产品经理、UI设计5个岗位，每个岗位6个话题。

内容是我**按照各岗位的技术知识体系手工编写的**——每条是一张知识点卡片，包含概念、面试评分标准、追问策略提示。

检索逻辑跟 Agent 决策联动：
- 决策=深挖弱点 → 检索最弱两个维度对应的知识点
- 决策=转话题 → 检索还没覆盖过的话题
- 决策=给提示 → 检索该岗位的基础概念条目

当前用内存索引，500条量级下检索<50ms。为什么没用 ChromaDB 向量库？第一，我的检索是**按决策类型和维度定位**的结构化检索，不是语义相似度搜索，JSON键值查找天然契合；第二，500条的量级没必要上向量库。架构上检索器抽象了 retrieve() 接口，后续换成向量检索只动一个类。"

### Q8：为什么用状态机不用 LangGraph/强化学习？

**回答模板：**

"项目初期方案里确实写了 LangGraph，但实现时我发现两个问题：
1. 面试决策需要**可解释性和可控性**。LangGraph 的节点编排能力适合流程编排，但最终决策如果依赖 LLM 节点，还是黑箱。我用手写状态机实现了它的核心思想——状态定义、状态流转、条件边——但决策全部是显式规则，每一轮'为什么这么决策'都能追溯。
2. 答辩和演示需要**确定性的行为**。RL 需要大量训练数据和环境交互，时间成本不现实；规则状态机在 50 组测试集上行为完全可预期。

我在论文里写的是'借鉴 LangGraph 的状态机设计思想'，这个说法是准确的。"

### Q9：评分合理性怎么验证的？

**回答模板：**

"三层验证：
1. **算法层**：50组多轮对话测试集（5岗位×10组），每条用例预设了预期决策，跑全量验证决策准确率目标≥85%
2. **数据层**：邀请10位水平不同的同学用系统做真实面试（录屏+录音），抽15段给3位评分员（2同学+1导师）独立打分，用 ICC 组内相关系数对比系统评分和人工评分的一致性
3. **对比层**：消融实验——关掉语音层看决策变化、关掉视觉层看决策变化，证明每个模态都贡献了独特信息；以及和固定题库模式的对比实验

同时我明确限定了系统定位：模拟训练工具，不做正式选拔，报告措辞只描述行为不推断特质。"

### Q10：最大的技术难点是什么？怎么解决的？

**回答模板（选一个讲透）：**

"印象最深的是 MediaPipe 的 WASM 加载黑屏问题。现象是摄像头打开后画面全黑，控制台报 `Cannot read properties of undefined (reading 'buffer')`。排查过程：先确认是 getUserMedia 的问题还是 MediaPipe 的问题——摄像头流本身能 play，是 FaceMesh 初始化时 WASM 预加载文件的二进制流没有 buffer 属性，CDN 在线加载链路断了。

解决：三级降级——本地离线WASM文件优先，CDN回退，再失败就切换 simulateFaceData() 生成平滑变化的模拟面部数据。核心教训是：**外部依赖必须有降级路径**，前端摄像头这类强交互功能尤其要兜底，不能让它把整个面试流程搞挂。"

### Q11：这个项目如果上线做生产级，你会改什么？

**回答模板（加分题，展示工程视野）：**

"1. 状态管理：当前会话状态存在后端内存字典里（_states），进程重启就丢，生产要接 Redis 持久化
2. LLM 生成质量：MockLLM 是模板出题，接真实 LLM 后需要加流式输出（SSE），现在是一次性返回，体验上有延迟感
3. 知识库：升级 ChromaDB 向量检索，支持语义相似问题
4. 音频格式：当前只支持16bit PCM WAV，要兼容 webm 直接解码
5. 测试：加单元测试和 CI，目前是手工+测试集验证"

### Q12：这个项目代码有多少是你自己写的？（AI辅助开发的必问题）

**诚实策略（不要吹牛，也不要自我贬低）：**

"我用 Codex 辅助开发，但分工是明确的：
- **AI 帮我做**：组件样板代码、CSS 布局、Mock 数据生成、报错排查建议
- **我做的**：整体架构设计（三层多模态+决策闭环是我定的）、18维评估体系的设计、7条决策规则的逻辑和阈值、知识库501条内容编写、API 接口定义、降级策略设计

我的判断标准是：**面试时问我任何一个模块的实现细节，我都能打开代码讲清楚每行逻辑**。比如决策规则为什么阈值定在35/50/70，压力指数为什么按0.35/0.35/0.15加权——这些设计决策是我做的，AI 只是把它们写成了代码。

另外我有一套完整的开发轨迹：交接文档、踩坑日志、50组测试集、Prompt架构文档，能证明我是逐步迭代过来的，不是一次生成。"

## 三、场景类突击问题（"如果XX怎么办"）

| 场景 | 回答要点 |
|---|---|
| 摄像头权限被拒怎么办 | getUserMedia 抛 NotAllowedError → 前端捕获，状态置 denied，弹提示；视觉4维自动填50分中性值，融合层权重再分配，面试照常 |
| MediaPipe 加载失败 | 三级降级，最终 simulateFaceData 生成自然波动的模拟数据，状态栏标注"模拟模式" |
| 后端 API 超时 | 前端 fetch 加了 AbortController，30秒超时；面试页有错误状态提示 |
| 两个候选人同时面试 | 每次进入面试生成 session_id，后端按 session_id 隔离状态（当前是内存字典，诚实说生产要换 Redis） |
| 面试中途刷新页面 | session_id 存前端变量，刷新后是新会话；历史记录已保存的会话可查报告 |
| 候选人乱回答（一句话/纯标点） | 文本分析信息密度维度会打低分（实体密度0+停用词惩罚），总分<35触发给提示或转话题规则 |
| 语音录了但没声音 | RMS 能量<0.005 判定"声音过轻"20分；VAD切不出有声段则语速/停顿维度返回中性分 |

## 四、每个模块的"考点速记卡"

### 后端文件结构（被问到"项目结构"时脱口而出）

```
src/backend/
├── main.py              # FastAPI入口，挂载路由
├── api/chat.py          # /api/chat 核心端点：接收多模态数据→编排7步流程
├── core/config.py       # pydantic-settings 读环境变量
└── services/
    ├── text_analyzer.py  # 文本5维（关键词/结构/术语/简历/密度）
    ├── voice_analyzer.py # 语音5维（纯标准库：wave+struct+math）
    ├── visual_analyzer.py# 视觉4维（FaceData 13特征评分）
    ├── fusion.py         # 融合层（一致性/压力/连贯/个性化）
    ├── agent.py          # 状态机+7条规则+知识检索器+执行器
    ├── llm.py            # BaseLLM抽象 + ChatGLM/Mock双实现
    └── report.py         # 报告生成
```

### chat.py 的7步编排（单轮请求的完整链路）

```
收到请求 → 解析多模态数据
→ text_analyzer.analyze_text()      # 文本5维
→ voice_analyzer.analyze_voice()    # 语音5维
→ visual_analyzer.analyze_visual()  # 视觉4维
→ fusion.fuse_analysis()            # 融合成18维
→ agent.process_turn()              # 状态机决策+知识检索+LLM生成
→ 返回 {decision, reply, dimensions, pressure_level, ...}
```

### 前端组件结构

```
app/page.tsx               # 首页：岗位选择+侧边栏路由
components/
├── ChatArea.tsx           # 面试主页面：三栏布局+对话编排
├── FaceCapture.tsx        # 摄像头+MediaPipe+模拟降级
├── VoiceRecord.tsx        # 录音+Web Speech API转写
├── ResumeUpload.tsx       # 简历上传（mammoth解析DOCX）
├── ReportView.tsx         # 报告页：SVG雷达图+18维+PDF/Word导出
└── RecordsView.tsx        # 历史记录
```

## 六、最后的提醒

1. **别背答案，记结构**。面试官换问法你就慌了——记住"三层架构+7条规则+18维+双模式降级"这条主线，细节顺着主线推。
2. **不确定的就说"这是我当时的考虑，可能有更优方案"**。承认局限比硬撑更专业。
3. **主动引导**。面试官问"讲讲项目"，你讲完30秒介绍后直接问："您想先听 Agent 决策部分还是多模态分析部分？"——把面试引到你准备最充分的方向。
4. **能演示就演示**。掏出手机打开 agent-interview.cn 当面跑一轮，比任何描述都有说服力。
5. **诚实是底线**。MockLLM 就是 MockLLM，模拟数据就是模拟数据。答得含糊被追问穿帮，比主动说明严重得多。
