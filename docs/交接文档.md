## STEP 04 · 源文档准则

### 核心定义
- **Agent**：不是简单 API 封装，必须实现意图识别、记忆、工具调用、任务规划的闭环
- **18 维分析**：Agent 的感知系统，不是最终目的，是为 Agent 决策提供数据
- **RAG 知识库**：≥500 条文档/节点，存储技术知识卡、评分标准、追问策略
- **多模态**：文本 + 语音 + 视觉，视觉放浏览器端本地处理（隐私合规）
- **测试集**：≥50 组对话路径，覆盖不同意图分支

### 导师 18 维表格（详见下方）
- 文本：关键词覆盖、结构逻辑、术语准确、简历匹配、信息密度
- 语音：语速节奏、停顿卡壳、语调情感、流利重复、音量清晰
- 视觉：眼神注意、面部表情、头部手势、形象背景
- 融合：内容情感一致性、压力评估、连贯时间、个性化出题 + 报告可视化

### 关键区别（答辩必讲）
| | 普通测评工具 | 本系统 |
|---|---|---|
| 出题 | 预设题库 | Agent 动态生成 |
| 追问 | 无 | 弱项深挖、强项跳过 |
| 状态感知 | 无 | 压力过大转话题 |
| 路径 | 千篇一律 | 千人千面 |

## 核心上下文重整（中间主模块）

### 一句话总结这个项目
> 一个会看人下菜碟的 AI 面试官——不是按顺序念题，而是根据你 18 维实时表现（答得怎样 + 紧不紧张 + 眼神表情），自己决定下一题问什么。

### Agent 闭环（最核心）
```
学生回答 → 文本5维+语音5维+视觉4维并行打分
         → 融合层(内容情感一致性、压力指数)
         → Agent决策: 深挖? 转题? 提示? 结束?
         → RAG检索 → ChatGLM出下一题
         → 循环
         → 复盘报告
```

### 技术栈速查
```
Next.js 14 | FastAPI | Celery+Redis | ChatGLM-6B | LangGraph
ChromaDB | text2vec | Whisper | librosa | MediaPipe | DeepFace
```
