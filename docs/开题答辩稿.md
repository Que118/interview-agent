各位老师好，我是 XXX，我的毕业设计题目是「基于多模态 Agent 的智能面试评估系统设计与实现」。

## 一、选题分类与规范对标

根据新修订的毕业设计规范，我的选题属于**「智能体交互设计」**类别。下面我从规范要求的四个维度逐一说明我的选题是如何满足的。

**第一，核心架构。**规范要求不能只是 API 的简单封装，必须实现 Agent 的核心机制。我的系统设计了一个完整的 Agent 决策引擎，基于状态机实现了四条清晰的决策路径——深挖弱点、转话题、给提示、结束面试。同时内置了意图识别模块来理解候选人回答、记忆模块来追踪跨轮次的上下文、工具调用模块来调度 RAG 知识检索和多维分析管道、任务规划模块来动态调整面试策略。七个后端服务模块协同工作，这完全符合规范中"不得仅为 API 简单封装"的要求。

**第二，交互体验。**规范要求支持多轮对话、上下文记忆和人格一致性，以及多模态输入输出。我的系统支持文本和语音两种输入方式——候选人可以打字回答，也可以直接说话，系统通过 Web Speech API 实时将语音转为文字。同时在浏览器端运行摄像头采集面部特征数据。AI 面试官在整个对话过程中保持专业、友善的人格一致性，会根据候选人的压力水平调整语气——紧张时给予鼓励，回答深入时追问细节。三栏式面试界面左边是多媒体输入面板，中间是对话区，右边是 Agent 实时状态面板，完全符合 AI 产品对话逻辑。

**第三，应用场景。**规范列举了虚拟数字人、智能导览、AI 陪伴助手等场景。我的系统定位是 AI 模拟面试官，属于智能交互系统在教育评估领域的实际应用，服务于高校学生和求职者的面试能力提升。

**第四，数据量。**规范要求不少于 500 条知识库节点和 50 组对话测试集。我的知识库目前包含 501 条结构化面试知识点，覆盖前端、后端、数据分析、产品经理和 UI/UX 设计五个岗位，每个岗位按六个话题维度组织。测试集设计了 50 组多轮对话路径，覆盖不同意图分支和决策走向。同时已编写了完整的 Prompt 架构设计文档。

## 二、主要设计思路

我的设计思路可以用一句话概括：**做一个会看人下菜碟的 AI 面试官**——它不是按照固定题库念题，而是根据候选人的实时表现，自己决定下一题问什么。

系统架构分为三层。最底层是**感知层**，三模态并行分析：文本分析通过关键词匹配和结构信号检测评估候选人的回答质量；语音分析提取语速、停顿、音高等韵律特征；视觉分析在浏览器端通过摄像头采集面部数据，检测眼神、表情和头部姿态——视觉分析完全本地运行，视频不上传服务器，保障隐私合规。

中间是**融合层**，将三模态的分析结果融合为 18 个维度的评估向量。18 维分成四组：文本 5 维包括关键词覆盖、结构逻辑、术语准确、简历匹配和信息密度；语音 5 维包括语速节奏、停顿卡壳、语调情感、流利重复和音量清晰；视觉 4 维包括眼神注意、面部表情、头部手势和形象背景；融合 4 维包括内容情感一致性、综合压力评估、时间连贯性和个性化综合评分。

最顶层是**Agent 决策层**，这是系统的核心创新。Agent 不是简单打分，而是根据 18 维评估结果自主做决策。表现优秀的维度转话题扩大考察面，薄弱的维度深挖追问确认真实水平，压力过高时给提示降低难度，轮次足够或表现极差时礼貌结束面试。Agent 的动态出题依赖 RAG 知识库——它根据决策类型和当前薄弱维度，从知识库中检索相关知识点，注入大语言模型的上下文，生成有针对性的下一题。

技术栈方面，前端用 Next.js 14 构建，后端基于 FastAPI，Agent 引擎的状态机设计借鉴了 LangGraph 的思路，知识库通过 ChromaDB 做向量检索为后续升级预留了接口。

## 三、总结

我的选题完全符合「智能体交互设计」分类的四个规范要求。核心创新在于将面试从传统"固定题库 + 被动打分"的测评工具范式，升级为"18 维实时感知 → Agent 自主决策出题"的自治系统，实现了千人千面的动态面试体验。
